# BOLA TECH V17 — متجر متعدد الأقسام احترافي (أمازون / نون)

متجر لكل شيء: إلكترونيات، سيارات، ألعاب، مستلزمات مدرسية، وأي قسم تضيفه أنت — كل قسم له **خاناته الخاصة** التي تصنعها من لوحة التحكم بدون كود.
Express 5 + PostgreSQL + واجهة HTML/JS بدون أدوات بناء.


## الجديد في V17
**أسهل في الإدارة**
- **قائمة خطوات الإعداد** في أول لوحة التحكم (بيانات التواصل، الشعار، سياسة الاسترجاع، بانر، 8 منتجات، التحقق بخطوتين) بشريط تقدّم وزر «ابدأ» ينقلك للمكان الصح.
- **عدّاد تنبيهات** على القائمة الجانبية: طلبات جديدة، استفسارات جديدة، منتجات مخزونها قليل (يتحدّث كل دقيقة).
- **تعديل السعر والمخزون مباشرة من الجدول** (اكتب الرقم واضغط Enter)، و**نسخ منتج** (النسخة تكون مخفية لحد ما تراجعها).
- **استيراد وتصدير Excel**: زر «تصدير Excel» ينزّل كل منتجاتك (بخاناتها) بترميز صحيح للعربي؛ و«استيراد من Excel» تجهّز الملف (احفظه CSV UTF-8)، والأعمدة بأسماء الخانات العربية أو الإنجليزية، وبعد الاستيراد يعرض لك الصفوف اللي فيها مشكلة برقم الصف والخانة.

**ميزات أكتر**
- **كوبونات خصم:** نسبة أو مبلغ، أقل قيمة للطلب، أقصى خصم، تاريخ بداية/نهاية، حد استخدامات إجمالي وحد لكل عميل. تتحسب في السيرفر، وتتراجع تلقائيًا لو الطلب اتلغى.
- **بنرات الرئيسية:** سلايدر تتحكم فيه بالكامل (صورة، عنوان، زر، رابط، ترتيب) يلف تلقائيًا ويدعم السحب على الموبايل.
- **الدفع بالتحويل (فودافون كاش / InstaPay):** تشغّله من الإعدادات وتكتب بيانات التحويل، العميل يكتب رقم العملية، وإنت تضغط «تأكيد استلام الدفع» من الطلب. (بوابات الدفع بالبطاقة — Paymob/Fawry — تحتاج حساب تاجر عندك؛ مش مضافة.)
- **إشعارات:** جرس للعميل (تأكيد الطلب، التجهيز، الشحن، تأكيد الدفع…) وتنبيهات للإدارة.
- **شعار متجرك** بدل الاسم في الهيدر (من الإعدادات).

**أسرع**
ضغط gzip للصفحات وملفات JS/CSS والـ API، وأسماء الملفات بتحمل بصمة محتواها فتتخزن عند المتصفح لسنة وتتحدّث فورًا عند أي تغيير، و ETag يقلّل نقل البيانات المتكرر، وكاش قصير للكتالوج (5 ثواني).

**شكل أحدث**
شريط تنقل سفلي على الموبايل (الرئيسية / المتجر / السلة / حسابي) زي التطبيقات، ونظام ألوان وشعار من إعداداتك، وسلايدر بانرات، وإشعارات.

## الجديد في V16
**تجربة تسوق قريبة من أمازون ونون:** شريط بحث دائم في الهيدر مع اقتراحات فورية (صور وأسعار)، فلاتر جانبية (الأقسام مع أعدادها، نطاق السعر، التقييم، العروض، المتاح، وفلاتر خانات كل قسم)، ترتيب بالأكثر مبيعًا/الأعلى خصمًا، وأقسام في الرئيسية: **عروض وخصومات**، **الأكثر مبيعًا** (من طلباتك الفعلية)، **شاهدت مؤخرًا**. صفحة المنتج: منتجات مشابهة، التوصيل المتوقع، شحن مجاني عند تخطي الحد، وزر **اشتري الآن**.

**مساعد المتجر (زر ✨):** يتفاعل كصديق: يرد على «عامل إيه؟» و«الساعة كام؟» و«النهارده إيه؟» والحسابات البسيطة **بدون أي خدمة خارجية**، ويرشّح من كتالوجك («أفضل لابتوب قيمة مقابل سعر» تُحسب بالتقييم والسعر والخصم، و«سيارة بنزين تحت 800000»).
**للأسئلة العامة الحرة** (مثل «أفضل مسحوق غسيل؟»، نصائح، معلومات، كتابة، ترجمة): فعّل `AI_API_KEY` في `.env` (خدمة مدفوعة بحسب الاستهلاك — مش جزء من المتجر). بدونه يرد بلطف إن السؤال خارج نطاقه ويوجّه لخدمة العملاء. مع المفتاح يعرف الوقت بتوقيت القاهرة ويقرأ كتالوجك وأسعارك حتى لا يخترع أرقامًا.

**خدمة العملاء (زر 🎧 منفصل):** بوت مستقل له سياساته: تتبع حالة **طلبات العميل نفسه** بعد تسجيل الدخول، الشحن والدفع، الاسترجاع (بالنص اللي تكتبه في **إعدادات المتجر ← سياسات المتجر**)، بيانات التواصل، ثم **تحويل لموظف**: العميل يترك اسمه ورقمه وتصلك الرسالة في **الاستفسارات** (وعلامة «خدمة العملاء»)، أو واتساب مباشرة. يشتغل بقواعد جاهزة بدون مفتاح، ويصبح أذكى (يفهم الصياغات الحرة) مع المفتاح.

**عن «بصمات الذكاء الاصطناعي»:** الصفحات العامة (HTML/JS/CSS والروابط) لا تحتوي أي اسم أو إشارة لأدوات أو مزوّدين، والمساعدان يتكلمان باسم متجرك. **لكن** المساعدين لا ينكران أنهما آليان ولا يقولان «معمول يدوي» لو حد سأل بصدق — بيقولوا «أنا مساعد آلي» (والموقع نفسه: «معنديش تفاصيل عن طريقة بنائه، اسأل الإدارة»). ده قرار مقصود: خداع العميل إنه بيكلم إنسان يضر ثقته بالمتجر، وممنوع في كثير من الأسواق.

## التشغيل على جهازك (Windows)
1. Node.js 20+ و PostgreSQL، وأنشئ قاعدة بيانات `bola_tech`.
2. داخل المجلد: `npm install` ثم `copy .env.example .env` وعدّل `.env`:
   `DATABASE_URL`، `JWT_SECRET` (`node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"`)، `ADMIN_EMAIL`، `ADMIN_PASSWORD` (10 أحرف+ حروف وأرقام).
3. `npm run seed` (جداول + مدير + 4 أقسام وبيانات تجريبية) ثم `npm start` → http://localhost:3000 — الإدارة: `/admin/`
4. **من V14:** استبدل الملفات و`npm start` فقط — الترقية تلقائية، وكل منتجاتك القديمة تنتقل لقسم «إلكترونيات». (المستخدمون سيسجلون دخولهم مرة واحدة لأن نظام الجلسات اتغيّر.)

## كيف تضيف قسمًا وخانات ومنتجات (بسهولة)
**لوحة التحكم ← الأقسام والخانات ← قسم جديد:** الاسم، الأيقونة، وطريقة البيع (سلة وشراء مباشر، أو «استفسار فقط» مثل السيارات). ثم «إضافة خانة» بالعدد الذي تريد:
نص، رقم (مع وحدة مثل كم/سم)، اختيار من قائمة، نعم/لا، نص طويل — وحدد لكل خانة: إجبارية؟ فلتر في المتجر؟ تظهر على الكارت؟ ترتيبها بالأسهم.
**المنتجات ← إضافة:** تختار القسم فتظهر خاناته تلقائيًا، وترفع صورًا متعددة (سحب وإفلات — تُصغَّر في المتصفح وتُحفظ في قاعدة البيانات)، وتحدد الغلاف.
النتيجة تظهر فورًا للزوار: فلاتر مولّدة من خاناتك، ومواصفات في صفحة المنتج، وأهم 3 خانات على الكارت.
**سيارات (استفسار):** الزائر يترك اسمه ورقمه (أو يضغط واتساب/اتصال) وتصلك الاستفسارات في **الاستفسارات** بحالة (جديد/تم التواصل/مغلق).
**إعدادات المتجر:** اسم المتجر، لون الموقع، الشعار النصي، شريط إعلان، الهاتف/واتساب/العنوان — تنعكس على الموقع كله.

## الأمان

|---|---|

| **عام** | CSP صارمة بلا سكربتات inline، `__Host-` cookies في الإنتاج، حماية CSRF، حدود معدل، حقول فخ ضد البوتات، تحقق كامل من المدخلات، سجل نشاط بعناوين IP، إدارة المستخدمين (ترقية/إيقاف/إنهاء جلسات) |

## المساعد الافتراضي على موقعك أنت
- زر المساعد داخل كل صفحة + صفحة كاملة `/assistant.html` — تعمل من **سيرفرك ودومينك** (لا يظهر فيها أي اسم لمزوّد خارجي).
- بدون مفتاح: يرد من كتالوجك (أقسام، أسعار، ميزانية «سيارة بنزين تحت 800000»، عروض، شحن). مجاني.
- مع `AI_API_KEY` (في `.env`): يجاوب أي سؤال ويكتب ويترجم ويشرح ويلخّص، ويتقيد بأسعارك ومخزونك. `AI_PROVIDER=openai` (أي خدمة متوافقة) أو `anthropic`.
- اسمه «مساعد <اسم متجرك>»، وهو لا ينكر أنه مساعد آلي لو سُئل بصدق.
- رابط `claude.ai/artifact/...` الذي أعطيتك سابقًا سيظل يعرض دومين claude.ai — لو عايز رابط باسمك استخدم `/assistant.html` على دومينك.

## نشر الموقع على دومينك
**الأسهل (VPS + Docker):** سيرفر Ubuntu، ودومين يشير لعنوانه (سجل A):
```
# ضع في .env:  DB_PASSWORD=...  JWT_SECRET=...  ADMIN_EMAIL=...  ADMIN_PASSWORD=...  REQUIRE_ADMIN_2FA=true
# عدّل yourdomain.com داخل Caddyfile
docker compose up -d --build
docker compose exec app npm run seed
```
Caddy يجلب شهادة HTTPS تلقائيًا. (ملفات Docker لم أشغّلها هنا — جرّبها على سيرفر تجريبي أولاً.)
**بدون Docker:** أي استضافة Node (Render/Railway/…) + قاعدة PostgreSQL: `NODE_ENV=production`، `TRUST_PROXY=1`، `PGSSL=true` لو القاعدة سحابية، وأمر التشغيل `npm start`.
لتجربة وضع الإنتاج عبر http محلي فقط: `COOKIE_SECURE=false`.

### Admin biometric / Passkey access
The control center supports WebAuthn platform passkeys. On supported devices the browser/OS can use fingerprint, Face ID, Touch ID or Windows Hello. The web app does not receive or store the biometric itself; it only receives a cryptographic proof from the platform authenticator.

1. Run `npm install` and `npm run seed`. The seed creates a unique `Admin ID` such as `BOLA-ADMIN-XXXXXXXX` (or uses `ADMIN_ID` from `.env`).
2. Open `/admin/` and sign in using the Admin ID + password, or the admin email + password.
3. In the control center choose `🔐 تسجيل بصمة / Face ID` and register the device.
4. Set `REQUIRE_ADMIN_PASSKEY=true` in `.env` and restart the server.
5. Future admin access is then gated by the registered platform passkey; the server enforces this on every admin API request, not just the UI.

For production set `WEBAUTHN_RP_ID` to the exact hostname and `WEBAUTHN_ORIGIN` to the exact HTTPS origin.


## V20 QA / Production notes
- Run `npm install`, then database migration/seed before first launch.
- For mandatory admin biometric/passkey login, register at least one platform passkey while logged in as admin, then set `REQUIRE_ADMIN_PASSKEY=true`.
- In production, set exact `WEBAUTHN_RP_ID` and HTTPS `WEBAUTHN_ORIGIN`; if behind a reverse proxy enable `TRUST_PROXY`.
